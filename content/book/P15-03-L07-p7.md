# P15-03-L07 — Lab cụm P7: Đo Render-blocking & Tối ưu một Trang

> **Tầng:** Học · **Văn kiện học cụm P7** · **Làm khi:** sau quiz Q07 · **Thời lượng:** 30–45 phút
> **Bản:** SA-2028.1 · **Cần:** Python 3 + curl (phần mô phỏng); trình duyệt + DevTools (phần đo trang thật)

---

## 1. Mục tiêu

Nắm bằng số khái niệm "render-blocking" của 7.1/7.3: parser HTML gặp `<script src>` không có `async/defer` phải **dừng tải xuống + thực thi** rồi mới đi tiếp — nên 3 script chặn nối tiếp = 3 lần trễ **cộng dồn**, trong khi `async/defer` cho chúng **chạy song song**. Phần mô phỏng đo đúng cấu trúc đó bằng curl; phần hai đo trang thật bằng DevTools.

## 2. Môi trường tối thiểu

Python 3 + curl. Máy chủ lab trả mọi tài nguyên sau 150 ms (mô phỏng độ trễ mạng + tải trọng).

## 3. Bước

1. Lưu `serv.py`:

```python
import http.server, threading, time
class H(http.server.BaseHTTPRequestHandler):
    def do_GET(self):
        time.sleep(0.15)                        # 150 ms/tài nguyên
        if self.path.endswith('.js'):
            body, ct = b'console.log("ok")', 'application/javascript'
        else:
            body, ct = ('<html><head><script src="/a.js"></script>'
                        '<script src="/b.js"></script><script src="/c.js"></script>'
                        '</head><body>x</body></html>').encode(), 'text/html'
        self.send_response(200); self.send_header('Content-Type', ct)
        self.send_header('Content-Length', str(len(body)))
        self.end_headers(); self.wfile.write(body)
    def log_message(self, *a): pass
http.server.ThreadingHTTPServer(('127.0.0.1', 8099), H).serve_forever()
```

2. Chạy `python3 serv.py &`, rồi đo hai mô hình (đo 2 lần mỗi mô hình):

```bash
B=http://127.0.0.1:8099
# A — parser chặn: html -> a.js -> b.js -> c.js (tuần tự)
time ( curl -s $B/index.html >/dev/null
       for j in a b c; do curl -s $B/$j.js >/dev/null; done )
# B — async/defer: html, rồi 3 script song song
time ( curl -s $B/index.html >/dev/null
       curl -s $B/a.js >/dev/null & curl -s $B/b.js >/dev/null &
       curl -s $B/c.js >/dev/null & wait )
```

3. Sửa `index.html` thêm `async` vào 3 thẻ script, mở `http://127.0.0.1:8099` bằng trình duyệt thật, F12 → tab Network (bật "Disable cache") — thấy 3 script tải chồng nhau thay vì xếp hàng.
4. Đo một **trang thật** của bạn: DevTools → Lighthouse → mục "Eliminate render-blocking resources".

## 4. Kết quả mong đợi

Đo thật (04/11/2026, 2 lần/mô hình): **A (chặn) = 640 ms** cả hai lần — đúng 4 bậc × 150 ms cộng thêm chi phí curl; **B (async) = 334 ms và 323 ms** — chỉ còn 2 bậc (html, rồi 3 script chồng nhau). Tỷ lệ **~2×**, và khoảng cách **tăng theo số script**: 10 script chặn = ~1,6 s, 10 script async vẫn ~0,3 s — vì sao bundle/Vite tách chunk tồn tại (7.3). Lưu ý trung thực: curl mô phỏng **phần tải xuống tuần tự** của hiện tượng; blocking thật còn gồm cả thời gian **thực thi** JS trên main thread — chỉ DevTools Performance (vạch "Parsing/Scripting") cho thấy đủ hai phần đó. INP/LCP trên trang thật mới là số cuối cùng (7.3 §3, 7.6).

## 5. Tự chấm

- Tính được: trang của bạn có N script chặn, mỗi script trễ `t` → FCP trễ thêm bao nhiêu? (`N × t` — cộng dồn);
- Phân biệt được khi nào dùng `defer` (giữ thứ tự, chạy trước DOMContentLoaded) và `async` (ai xong nấy chạy — 7.1);
- Nêu 1 script thật trên trang bạn nên `defer` ngay hôm nay và cách kiểm chứng bằng DevTools trước-sau.
