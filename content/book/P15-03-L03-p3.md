# P15-03-L03 — Lab cụm P3: RSS và hành vi GC của hai Runtime dưới cùng tải

> **Tầng:** Học · **Văn kiện học cụm P3** · **Làm khi:** sau quiz Q03 · **Thời lượng:** 30–45 phút
> **Bản:** SA-2028.1 · **Cần:** Python 3 + Node.js — hai script, không thư viện ngoài

---

## 1. Mục tiêu

Đo bằng mắt hai điều mà 3.1 nói bằng lý thuyết: (1) **RSS ≠ số đối tượng còn sống** — bộ nhớ đã cấp không tự trả lại hệ điều hành sau GC; (2) hai runtime, cùng tải, hai hành vi trả bộ nhớ khác nhau. Đây là gốc của "service ăn RAM rồi không thả" (3.9).

## 2. Môi trường tối thiểu

`python3` và `node` (≥ 18). Tải: tạo 2 triệu đối tượng nhỏ, giữ mỗi phần mười, ép GC, đo RSS.

## 3. Bước

1. Lưu `l03.py`:

```python
import gc
def rss():
    for l in open('/proc/self/status'):
        if l.startswith('VmRSS'):
            return int(l.split()[1])                    # kB
base, keep = rss(), []
for i in range(2_000_000):
    o = {'id': i, 'name': 'item-%d' % i, 'tags': ['a', 'b']}
    if i % 10 == 0:
        keep.append(o)
gc.collect()
d = rss() - base
print('giữ %d · RSS %d → %d kB (tăng %d kB ≈ %.0f B/obj giữ)'
      % (len(keep), base, rss(), d, d * 1024 / len(keep)))
```

2. Lưu `l03.js`, chạy với `node --expose-gc l03.js`:

```js
function rss() { return process.memoryUsage().rss / 1024; }   // kB
const base = rss(), keep = [];
for (let i = 0; i < 2e6; i++) {
  const o = { id: i, name: 'item-' + i, tags: ['a', 'b'] };
  if (i % 10 === 0) keep.push(o);
}
global.gc();
const d = rss() - base;
console.log(`giữ ${keep.length} · RSS ${Math.round(base)} → ${Math.round(rss())} kB `
  + `(tăng ${Math.round(d)} kB ≈ ${Math.round(d * 1024 / keep.length)} B/obj giữ)`);
```

3. Chạy mỗi bản 2 lần. Rồi đổi `i % 10` thành `i % 2` (giữ 1 triệu) và chạy lại.

## 4. Kết quả mong đợi

Đo thật trên Linux 2 GB RAM (04/11/2026, 2 lần chạy lệch <5%): Python giữ 200.000 obj → RSS tăng **~74 MB ≈ ~380 B/obj**; Node cùng tải → **~46 MB ≈ ~235 B/obj**. Giữ 1 triệu: cả hai tăng gần tuyến tính. Điểm mấu chốt **không phải** con số tuyệt đối mà là hai quan sát: sau `gc.collect()`/`global.gc()` với 90% đối tượng đã chết, RSS **không về lại mức cũ** (Python giữ arena phân mảnh; V8 trả một phần old-space); và cùng tải, hai runtime chênh nhau cả trăm byte/obj chỉ vì cách lưu đối tượng khác nhau (3.1 §2). Trên macOS thay `/proc` bằng `ps -o rss= -p $$` (Python) hoặc dùng `process.memoryUsage().rss` (Node có sẵn).

## 5. Tự chấm

- Trả lời được: 1,8 triệu đối tượng đã chết, vì sao RSS không giảm tương ứng? (cấp phát theo arena/generation — 3.1);
- Tính được B/obj giữ của máy bạn cho cả hai runtime và nêu 1 lý do chúng chênh nhau;
- Nêu 1 quyết định vận hành bị hai con số này đổi (đặt memory limit bao nhiêu cho container chạy service này — kèm hệ số an toàn, 3.9).
