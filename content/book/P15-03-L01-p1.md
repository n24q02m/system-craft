# P15-03-L01 — Lab cụm P1: Đo Bậc thang Bộ nhớ (cache vs RAM)

> **Tầng:** Học · **Văn kiện học cụm P1** · **Làm khi:** sau quiz Q01 · **Thời lượng:** 30–45 phút
> **Bản:** SA-2028.1 · **Cần:** Linux/macOS có `gcc` — đo trên máy thật của bạn

---

## 1. Mục tiêu

Thấy **bằng tay** cái bậc thang mà 1.1 chỉ bằng bảng số: một lần đọc bộ nhớ mất bao lâu tuỳ thuộc dữ liệu nằm ở L1, L2, L3 hay RAM — và vì sao "thuật toán thân cache" thắng "thuật toán ít phép tính" (1.2).

## 2. Môi trường tối thiểu

`gcc`. Chương trình đuổi con trỏ qua một **vòng hoán vị ngẫu nhiên**: lần đọc sau phụ thuộc lần đọc trước → đo độ trễ thuần, không bị lệnh song song che mất.

## 3. Bước

1. Lưu `bench.c`:

```c
#include <stdio.h>
#include <stdlib.h>
#include <time.h>
static double now(void) {
    struct timespec ts; clock_gettime(CLOCK_MONOTONIC, &ts);
    return ts.tv_sec + ts.tv_nsec * 1e-9;
}
int main(void) {
    size_t kb[] = {16, 256, 4096, 65536, 262144, 524288};   /* L1 → RAM */
    for (unsigned s = 0; s < sizeof(kb)/sizeof(kb[0]); s++) {
        size_t n = kb[s] * 1024 / sizeof(size_t);
        size_t *a = malloc(n * sizeof(size_t)), *next = malloc(n * sizeof(size_t));
        if (!a || !next) { printf("%lu KiB: hết bộ nhớ\n", kb[s]); continue; }
        for (size_t i = 0; i < n; i++) a[i] = i;
        for (size_t i = n - 1; i > 0; i--) {              /* Fisher–Yates */
            size_t j = (size_t)((double)rand()/RAND_MAX*(i+1));
            size_t t = a[i]; a[i] = a[j]; a[j] = t;
        }
        for (size_t i = 0; i < n; i++) next[a[i]] = a[(i+1) % n];   /* nối thành 1 vòng */
        free(a);
        volatile size_t p = next[0];
        size_t iters = n < 2000000 ? (2000000/n + 1)*n : n;        /* ≥ 2 triệu lần đọc */
        double t0 = now();
        for (size_t k = 0; k < iters; k++) p = next[p];
        printf("%-6lu KiB   %.1f ns/lần đọc\n", kb[s], (now()-t0)*1e9/iters);
        free((void*)next); (void)p;
    }
    return 0;
}
```

2. Biên dịch và chạy 3 lần: `gcc -O2 -o bench bench.c && ./bench && ./bench && ./bench`
3. Ghi bảng kết quả của máy bạn cạnh bảng mẫu dưới.

## 4. Kết quả mong đợi

Đo thật trên một Xeon 2,6 GHz, Linux, RAM 2 GB (04/11/2026 — 3 lần chạy lệch nhau <10%):

| Working set | ns/lần đọc | Nơi dữ liệu nằm |
|---|---|---|
| 16 KiB | 1,6 | L1 |
| 256 KiB | 4,5 | L2 |
| 4 MiB | 36–44 | L3 |
| 64 MiB | ~160 | mép L3 |
| 256–512 MiB | 180–200 | RAM |

Máy bạn ra số khác — không sao: **cái để so là các bậc** (kiểu 1 → ~3 → ~10 → ~100 ns), không phải giá trị tuyệt đối. Không thấy bậc nào? Tăng dải working set — máy RAM lớn thường L3 cũng lớn. Bậc "nấp" ở 4 MiB là chỗ cache phân cấp giao nhau.

## 5. Tự chấm

- Bảng có ≥ 4 bậc phân biệt được và bạn chỉ được bậc nào là cache, bậc nào là RAM;
- Giải thích được vì sao thời gian ở 512 MiB không tăng theo đúng tỷ lệ số byte (TLB, prefetch, nội dung vòng lặp nhỏ);
- Nêu 1 quyết định thật của bạn bị bậc thang này đổi (ví dụ: cấu trúc dữ liệu nào nên chuyển sang mảng phẳng — 1.2).
