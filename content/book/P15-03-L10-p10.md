# P15-03-L10 — Lab cụm P10: Đo Timing Enumeration trên Form Đăng nhập

> **Tầng:** Học · **Văn kiện học cụm P10** · **Làm khi:** sau quiz Q10 · **Thời lượng:** 45 phút
> **Bản:** SA-2028.1 · **Cần:** Python 3 — server + client đo chạy chung một máy

---

## 1. Mục tiêu

Tự dựng một lỗ hổng rồi tự vá nó: form đăng nhập trả lời **nhanh cho user không tồn tại, chậm cho user có thật** (vì chỉ user có thật mới đi kiểm tra mật khẩu) — khoảng chênh millisecond là đủ để kẻ tấn công **dò danh sách user hợp lệ** mà không cần đoán đúng mật khẩu. Đây là side-channel thời gian của 14.11.1 dưới dạng web, đối tượng A07 của 10.4.

## 2. Môi trường tối thiểu

Python 3. Server lab: `alice` có thật (kiểm tra mật khẩu bằng PBKDF2 tốn ~11 ms), `bob` không tồn tại. Client đo: gửi POST `/login` 25 lần cho mỗi tên, lấy median.

## 3. Bước

1. Lưu `l10serv.py` (bản thu gọn ~30 dòng từ bản đo):

```python
import http.server, hashlib, os
USERS = {'alice': b'$alt-ca-thu' + b'x' * 32}
FIX = os.path.exists('/tmp/l10_fixed')          # chế độ vá
class H(http.server.BaseHTTPRequestHandler):
    def do_POST(self):
        n = int(self.headers.get('Content-Length', 0))
        form = dict(p.split(b'=') for p in self.rfile.read(n).split(b'&') if b'=' in p)
        user = form.get(b'user', b'').decode()
        if user in USERS:
            hashlib.pbkdf2_hmac('sha256', b'sai-cho-biet', USERS[user], 60_000)   # tốn kém
        elif FIX:
            hashlib.pbkdf2_hmac('sha256', b'sai-cho-biet', b'dummy', 60_000)      # vá: cũng tốn
        self.send_response(401); self.send_header('Content-Length', '6')
        self.end_headers(); self.wfile.write(b'denied')
    def log_message(self, *a): pass
http.server.ThreadingHTTPServer(('127.0.0.1', 8098), H).serve_forever()
```

2. Đo với `http.client` (25 lần/user, lấy median, min, max) cho `alice` và `bob`.
3. `touch /tmp/l10_fixed` rồi restart server, đo lại cả hai.

## 4. Kết quả mong đợi

Đo thật (04/11/2026, cùng máy, 25 mẫu): **lỗ hổng — alice median 11,5 ms · bob median 0,5 ms → chênh 11 ms (22×)**: đủ nhiễu để lừa, đủ ổn định để thống kê — kẻ tấn công dò 100 tên, ai "chậm" là user thật. **Sau vá — alice 11,1 ms · bob 11,2 ms → chênh −0,1 ms**: cả hai đường đều tốn chi phí kiểm tra như nhau, tín hiệu Timing bị xóa. Đây chính là nguyên tắc constant-time của 10.2/14.11.1: không tiết lộ thông tin qua *thời gian*. Lưu ý trung thực: ở đây server trả cùng mã 401 cho mọi trường hợp — nếu mã lỗi hay thông điệp khác nhau thì kênh rò rỉ còn thô hơn nữa (user enumeration qua response — 10.4).

## 5. Tự chấm

- Giải thích được vì sao median tốt hơn mean khi đo timing online (nhiễu đuôi, jitter mạng — 6.4);
- Nêu 3 nơi mã của bạn có thể rò rỉ timing ngoài login: kiểm tra user, so sánh token, phân nhánh theo quyền (10.3, 14.11.1);
- Trả lời: vá bằng "delay cố định sleep 11 ms cho mọi request" có phải giải pháp tốt không, và vì sao (không — tốn CPU vô ích và vẫn rò rỉ nếu chi phí thật đổi theo dữ liệu; đúng cách là làm chi phí độc lập với bí mật).
