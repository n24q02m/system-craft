## 1. Mục tiêu

Trải bằng tay nguyên lý local-first của 6.3: khi kênh gửi hỏng 30%, gửi thẳng = **mất dữ liệu**, gửi qua **hàng đợi + thử lại + idempotency** = không mất gì, chỉ trễ. Kèm tay: hiểu at-least-once và vì sao phải chống trùng lặp (5.7, 6.3 §3).

## 2. Môi trường tối thiểu

Python 3, một file. Proxy "xấu" nghe cổng 9000, chuyển tiếp sang sink 9001: 30% kết nối bị cắt ngay, còn lại mỗi gói trễ 40 ms — đúng vai trò của `netem loss/delay` khi bạn không có Linux thật (có thì thay bằng `tc qdisc add dev lo root netem delay 40ms loss 30%`).

## 3. Bước

1. Lưu `demo.py` (~55 dòng, thu gọn từ bản đo):

```python
import socket, threading, time, random, queue, json
random.seed(7); received = set()
def sink():                                  # máy nhận: ghi id sự kiện
    s = socket.socket(); s.setsockopt(socket.SOL_SOCKET, socket.SO_REUSEADDR, 1)
    s.bind(('127.0.0.1', 9001)); s.listen(16)
    while True:
        c, _ = s.accept()
        threading.Thread(target=lambda c: [received.add(
            json.loads(c.recv(65536))['id']), c.sendall(b'ok'), c.close()],
            args=(c,), daemon=True).start()
def bad_proxy():                             # 9000 -> 9001: 30% cắt, còn lại trễ 40 ms
    s = socket.socket(); s.setsockopt(socket.SOL_SOCKET, socket.SO_REUSEADDR, 1)
    s.bind(('127.0.0.1', 9000)); s.listen(16)
    while True:
        c, _ = s.accept()
        def relay(c):
            if random.random() < 0.3: c.close(); return
            up = socket.create_connection(('127.0.0.1', 9001))
            try:
                data = c.recv(65536); time.sleep(0.04); up.sendall(data)
                up.settimeout(2); c.sendall(up.recv(4096))
            except Exception: pass
            finally: c.close(); up.close()
        threading.Thread(target=relay, args=(c,), daemon=True).start()
def send_once(ev):
    try:
        c = socket.create_connection(('127.0.0.1', 9000), timeout=1); c.settimeout(1)
        c.sendall(json.dumps(ev).encode()); ok = c.recv(64) == b'ok'; c.close(); return ok
    except Exception: return False
threading.Thread(target=sink, daemon=True).start()
threading.Thread(target=bad_proxy, daemon=True).start(); time.sleep(0.3)
events = [{'id': i, 'v': i * 7} for i in range(100)]
lost = sum(1 for e in events if not send_once(e))          # A: gửi thẳng
print('A. KHÔNG hàng đợi: %d/100 thành công · %d MẤT' % (100 - lost, lost))
q = queue.Queue()
for e in events: q.put(e)
t0, tries, sent = time.time(), 0, 0
while not q.empty():                                        # B: hàng đợi + thử lại
    e = q.get(); tries += 1
    if send_once(e): sent += 1
    else: time.sleep(0.15); q.put(e)                        # backoff, xếp lại cuối hàng
print('B. CÓ hàng đợi: %d/100 đến đích · %d lần gửi · %.1f s'
      % (sent, tries, time.time() - t0))
time.sleep(0.3); print('sink nhận: %d sự kiện, trùng: %d' % (len(received), sent - len(received)))
```

2. `python3 demo.py` — chép lại hai dòng kết quả A và B.
3. Đổi seed `random.seed(11)` chạy lại — kênh xấu đổi, kết cục có đổi không?

## 4. Kết quả mong đợi

Đo thật (04/11/2026): **A — 67/100 gửi thành công, 33 sự kiện MẤT hẳn**; **B — 100/100 đến đích sau 152 lần gửi (52 lần thử lại) trong 12,0 s, sink nhận đúng 100, trùng lặp 0**. Thứ lab dạy không phải "hàng đợi nhanh hơn" — nó **chậm hơn** (12 s) — mà là **đáng tin hơn**: đúng cam kết at-least-once của mọi message queue thật (5.7). Với seed khác: số lần thử đổi, kết cục 100/100 không đổi. Nếu bạn phản biện "thử lại có thể khiến sink nhận trùng" — đúng: bản demo tránh trùng vì chỉ gửi lại khi **chắc chắn** chưa được ack trong phiên đó; môi trường thật (ack bị mất sau khi sink đã ghi) cần thêm idempotency key ở sink (6.3 §3).
